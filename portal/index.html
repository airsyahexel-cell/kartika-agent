[KRITIS]  1. Transmisi Kredensial Tanpa Enkripsi (Cleartext HTTP)
   • Bukti: target merespons di HTTP (Port 80) tanpa 'Strict-Transport-Security' maupun pengalihan HTTPS.
[WASPADA] 2. Kebocoran Sidik Jari Teknologi

   • Bukti: tidak ada 'X-Frame-Options', 'Content-Security-Policy', 'X-Content-Type-Options'.

REKOMENDASI: aktifkan HTTPS + HSTS, sembunyikan banner versi di 'web.config', terapkan security headers di reverse proxy / IIS.

Paradigma operasi

Berbasis misi, diverifikasi dengan bukti, dan bisa ditanam di mana saja — dari posko operator sampai CI/CD satuan.

Mode Posko — shell taktis interaktif

Beri direktif misi langsung di terminal MISI>; agen membalas dengan format SITREP: Temuan, Bukti Validasi, Dampak, dan Langkah Mitigasi.

Mode Senyap — headless --mission

Eksekusi satu baris tanpa interaksi, cocok untuk CI/CD pipeline agar kode rentan tidak naik ke produksi (exit code non-zero saat misi gagal).

Verifikasi berbasis bukti

Setiap indikasi kelemahan dicek lewat alur logika kode dan header/struktur respons aktual, lalu dicatat sebagai Catatan Bukti Teknis beserta patch perbaikan terukur.

AI berdaulat & agnostik

Standar OpenAI-Compatible Chat Completions: ganti KARTIKA_API_URL, KARTIKA_API_KEY, KARTIKA_MODEL untuk beralih otak AI tanpa ubah kode.

Mode air-gapped

Tanpa koneksi keluar, engine berjalan penuh di Ollama atau vLLM internal. Untuk pengujian, arahkan ke Groq / Gemini / OpenRouter / OpenAI.

Ekstensibel via MCP

Membaca mcp.json, menyalakan MCP Server sebagai child process, handshake initialize, lalu menyerap tools/list — tanpa menyentuh kode inti.

Alur pembentukan & runtime

Lima tahap build pipeline, lalu siklus ReAct + Verification Loop di setiap misi.

Siklus eksekusi misi

Urutan yang dijalankan agen pada setiap misi.

  1. Bootstrapping — memuat konfigurasi LLM, membaca mcp.json, menyatukan modul bawaan + MCP ke satu registri JSON Schema.
  2. Input direktif misi — lewat terminal interaktif (mode posko) atau flag --mission (mode senyap).
  3. Fase 1 RECON — memetakan struktur direktori (scan_dir) atau profil target (http_probe).
  4. Fase 2 INSPECT & VERIFY — membaca source code (read_file), membedah header, atribut cookie, dan form HTML untuk menyingkirkan false positive.
  5. Fase 3 REPORT & REMEDIATE — merangkum hasil ke SITREP dan menulis file patch/rekomendasi (write_file).

Ekspansi modul via mcp.json

Perluas kemampuan agen kapan saja (Git forensics, SQLite inspection, Docker audit, network diagnostics) tanpa mengubah kode inti Golang.

{
  "mcpServers": {
    "filesystem": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", "."] },
    "git":        { "command": "uvx", "args": ["mcp-server-git", "--repository", "."] },
    "sqlite":     { "command": "uvx", "args": ["mcp-server-sqlite", "--db-path", "./app.db"] }
  }
}
Etika operasi. KARTIKA-AGENT hanya untuk audit sistem milik sendiri atau sistem yang telah mendapat izin tertulis. Penggunaan terhadap target tanpa izin melanggar hukum dan disiplin satuan.
