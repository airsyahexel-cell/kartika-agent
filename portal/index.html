Paradigma Operasi

Mission-driven, verifikasi berbasis bukti, dan bisa ditanam di mana saja — dari posko operator sampai CI/CD satuan.

MODE POSKO — Interactive Tactical Shell

Operator memberi direktif misi langsung di terminal MISI>; agen merespons dengan format SITREP yang tegas: Temuan, Bukti Validasi, Dampak, dan Langkah Mitigasi.

MODE SENYAP — Headless --mission

Eksekusi satu-baris tanpa interaksi manual, cocok ditanamkan ke CI/CD pipeline untuk memblokir kode rentan naik ke produksi (exit code non-zero saat misi gagal).

EVIDENCE-BASED VERIFICATION

Agen tidak berhenti pada asumsi permukaan. Setiap indikasi kelemahan diverifikasi lewat alur logika kode, header/struktur respons aktual, lalu dicatat sebagai Catatan Bukti Teknis + patch perbaikan terukur.

SOVEREIGN & AGNOSTIC AI

Standar OpenAI-Compatible Chat Completions: ganti KARTIKA_API_URL, KARTIKA_API_KEY, KARTIKA_MODEL untuk beralih antar-otak AI — tanpa mengubah kode.

MODE AIR-GAPPED

Di markas/satuan tanpa koneksi keluar, engine berjalan penuh di atas Ollama atau vLLM internal. Di fase pengujian, cukup arahkan ke Groq / Gemini / OpenRouter / OpenAI.

EKSTENSIBEL VIA MCP

Agen membaca mcp.json, menyalakan MCP Server eksternal sebagai child process, handshake initialize, lalu menyerap tools/list sebagai modul taktis tambahan — tanpa menyentuh kode inti.

Alur Pembentukan & Runtime

Lima tahap build pipeline dan siklus ReAct + Verification Loop di setiap misi.

[Tahap 1: Inisialisasi Core Engine]        — setup modul Go & environment (API_URL, API_KEY, MODEL)
   ▼
[Tahap 2: Built-in Tactical Modules]       — scan_dir, read_file, http_probe, write_file
   ▼
[Tahap 3: Integrasi MCP Stdio Bridge]      — parser mcp.json → spawn subprocess → JSON-RPC handshake → tool discovery
   ▼
[Tahap 4: ReAct Loop & Verification]       — recon → inspect & verify evidence → SITREP + remediation patch
   ▼
[Tahap 5: Cross-Compilation & Distribusi]  — binary Linux/Windows/macOS → GitHub Releases → Vercel portal

Siklus Eksekusi Misi

  1. Bootstrapping — memuat konfigurasi LLM, membaca mcp.json, menyatukan modul bawaan + modul MCP ke satu registri JSON Schema.
  2. Input Direktif Misi — melalui terminal interaktif (mode posko) atau flag --mission (mode senyap).
  3. Fase 1 RECON — pemetaan struktur direktori (scan_dir) atau pengambilan profil target (http_probe).
  4. Fase 2 INSPECT & VERIFY — membaca source code (read_file), membedah header, atribut cookie, dan elemen form HTML untuk memastikan kelemahan valid (menyingkirkan false positive).
  5. Fase 3 REPORT & REMEDIATE — merangkum hasil validasi ke laporan SITREP dan menulis file patch/rekomendasi konfigurasi (write_file).
